## Library
github.com/danielpaulus/go-ios (MIT, v1.3.2, needs Go 1.26+; repo uses 1.27.1). Talks to Apple Mobile Device Service (usbmuxd, 127.0.0.1:27015; comes with Apple Devices / iTunes). Installs via com.apple.streaming_zip_conduit (what Xcode uses): `zipconduit.New(device).SendFile(ipa)`. Device info: `ios.ListDevices()`, `ios.GetValues(d)` -> Value.DeviceName / ProductType / ProductVersion. No Apple account or Apple servers involved ([[protect-apple-account]] unaffected). The .ipa is sent unchanged, never re-signed.

## Steps (small buildable commits, [[no-coauthor]])
1. **gui/install.go:** `connectedPhones()` (name, model, iOS version); `installIPA(ctx, path, progress)` reporting the phone's statuses. Plain-language errors ([[plan-clearer-errors]]), matched by code not go-ios wording: no phone / phone locked / "Trust this computer" not answered / Apple Mobile Device Service missing (install Apple Devices or iTunes) / 0xe8008029 "Your iPhone refused this version. Its signature is too old for your iOS version. Try a newer version of the app." / not enough space / 32-bit-only app.
2. **Signature pre-check:** read the main binary with Go debug/macho (thin + fat), LC_CODE_SIGNATURE SuperBlob -> CodeDirectory version + hash types; warn but let the user still try: 32-bit only -> "This app can't run on iOS 11 or later"; CodeDirectory below 0x20400 -> "This app has an old signature. iOS may refuse it". No Apple requests. Unit tests on small synthetic Mach-O blobs.
3. **Download page** (no ending punctuation, [[no-control-punctuation]]): button "&Install on iPhone" (Alt+I; Download page only - Alt+I on My apps is the availability filter, different page) installs the file just downloaded this session, else opens a .ipa file picker; check box "Install on iPhone after do&wnload" (Alt+W, unticked by default, saved in settings.json). Progress/result in the Result field; cancellable task (tasks.go); focus like the Download button. Several phones -> list dialog to pick one, with first-letter nav ([[lists-first-letter-nav]]).
4. **README** (REQUIRED by the user when the feature is built):
   - "Install on iPhone" - how it works: USB, Apple Mobile Device Service, unchanged install like iTunes, never re-signed, no Apple requests, progress in the Result field.
   - CAUTION: apps only open on a phone that has been signed into the buying Apple ID at some point (keys stay after sign-out); signing into ipatool does NOT authorize a phone; a never-signed-in phone probably won't open them (untested); updates ask for the buying account's password; sharing purchases outside Family Sharing breaks Apple's terms and means sharing the password - don't share accounts; some old builds refused ("code signature version is no longer supported"); 32-bit-only apps can't run on iOS 11+; deleting an app erases its data.
   - "App signing" explainer, plain language: TYPES - development, ad hoc (up to 100 registered devices), enterprise/in-house, TestFlight, App Store distribution (re-signed by Apple), free sideload certs that expire after 7 days. METHODS - code signature in the Mach-O (CodeDirectory with per-page hashes, its versions e.g. 0x20200/0x20400/0x20500, SHA-1/SHA-256 hash types, entitlements, CMS signature + Apple certificate chain); provisioning profiles; FairPlay encryption with the per-account license (sinf) + account keys on the phone; why re-signing (Sideloadly) breaks FairPlay (Codename Cygnus crash); why Apple may re-sign old apps (Yahoozy example).
   - Update F1 shortcuts text (main.go shortcutsHelp).
5. **Tests:** unit tests for error mapping + signature reader; GUI checks on the hidden desktop only ([[gui-tests-hidden]]); automated tests never install on a phone.
6. **Build** both programs into releases\ipatool ([[build-output-folder]]).
